# Parent-to-child improver transfer

This completed experiment is the strongest direct test so far of whether an improver becomes better at improving. It **did not pass**. A later parent was admitted after an external admission panel, but its child improver did not outperform the initial child, scrambled-history child, duplicate-history child, or the strongest fixed schedule on untouched transfer banks.

## Protocol and evidence

The experiment used a bounded edit catalog for cross-family output-query allocation. Parent states were initial, later, scrambled-feedback and duplicate-history. A separate six-bank admission panel exposed 288 verified task effects and allowed a protected later-versus-transform/mutation admission decision. Two untouched six-bank transfer panels (12 banks, 576 tasks) then compared children from each parent at the same eight-call-per-bank logical budget against fixed AST-only, transform-only, mutation-only, balanced and random schedules. Candidate pools, public features, output predictions, exact labels and model files were replayed by the existing [audit](runs/cross-family-meta-improver-transfer-20260918/audit.json).

Admission passed: later minus transform/mutation was +10 total over six banks, with four positive and one losing bank. That admission result was not used to tune transfer outcomes. The final synthesis was generated by `cross_family_meta_improver_transfer.py final` only after admission, child training and both transfer panels were complete.

Later minus initial differences across the 12 independent transfer banks were `[0, 0, -1, 0, 0, 0, 1, 0, 0, 0, -1, -1]`: one positive bank, three losing banks, total -2, paired bank-bootstrap interval **-6 to +2**. The primary child gate failed. Later also trailed the strongest fixed schedule (interaction-10) by three tasks overall. The protected later policy was correctly rejected for transfer because its admission gate was not enough to establish child growth.

The experiment's audit covered the admission and transfer stages; the root `summary.json` contains the full bank-level records, and `audit.json` reports the reconstructed source and target artifacts. This is a genuine same-base parent-to-child negative result, not merely a failure to beat a solver baseline. It shows that an admitted parent can select useful changes on its admission panel without transmitting a stronger improvement policy to a new base.

## What this teaches the seed design

The current best supported seed is a composite, not a recursively growing improver: use task-level listwise ranking as a scoped evaluator-training principle, the dual-specialist route as the lower-cost AST fallback, and exact output checks as a costed action. The improver should not yet inherit a later effect table as if it were knowledge. In this test, effect history and a parent admission decision did not compound into a better child.

The next improver design needs more persistent edit state and more independent edit effects. It should model not just immediate task gain, but the probability that an edit produces useful descendants, while preserving negative effects and cost. Its parent-to-child test must keep the same base solver, separate admission and transfer mechanisms, include search/generator and ranking-objective edits alongside sensor allocation, and require the child improver to beat initial, scrambled, duplicate and fixed controls on a second untouched bank. Until that passes, the system has evaluator improvements and useful solver actions, but no demonstrated positive recursive feedback loop.
