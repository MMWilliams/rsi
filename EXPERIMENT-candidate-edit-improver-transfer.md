# Frozen candidate-edit parent/child transfer

Frozen 2026-09-18 while the new 902522-902533 bank was being prepared, before its final labels were scored or inspected. This is a separate exploratory improver experiment on that untouched bank; its 12 seeds and base candidate pools were already fixed in `EXPERIMENT-candidate-reranker-replication.md`.

## Same-base child construction

Use only the 576 previously audited task-level edit-effect records in `analysis/candidate-edit-effect-ledger-20260918.json`. The initial parent inherits the first six 48-task source banks (288 records). The later parent inherits all twelve (576 records). A scrambled parent inherits the first six intact and the second six with each complete ranker/query outcome vector rotated within the same public family; this preserves family totals but disrupts task-feature credit. A duplicate parent inherits the first six twice, controlling the size of the table without adding information. No fresh final labels enter training.

Each parent uses the same fixed child-construction rule. For each public mechanism, start with E1 and choose a different ranker among old/E0/E1/7-leaf only when its source zero-query success count exceeds E1 by at least two. Ties retain E1. Fit the frozen `family_100` ridge query-gain rule to the verified one-call-minus-zero-call effects of the chosen ranker, using the existing 12 public query features and mechanism one-hot. On a 48-task bank, buy the eight tasks with highest predicted gain. The public mechanism route and eight task IDs together constitute the child policy. All four children are applied to the same frozen pool and candidate/probe predictions. They get the same eight true output calls per bank. The old fixed E1 reranker with the old frozen E0 allocator is the deployment control.

Freeze route tables, fitted model coefficients, chosen calls and source hashes before opening new final labels. The first six new banks are admission; the final six are protected transfer. Admission accepts the later child only if it matches or exceeds both the initial child and fixed E1 control. The primary transfer endpoint is later-child minus initial-child correct final choices on the final six banks. A growth claim additionally requires at least +4 correct tasks, at least four positive banks, a positive exact paired bank-bootstrap lower endpoint, later child ahead of scrambled and duplicate children, and later child at least the fixed E1 control. Report any failed condition without relaxing the gate. Record both no-query and eight-call effects, public route, acquired labels, rescoring/prediction work and output calls.

This tests a bounded, researcher-written improver with an inherited effect table. Even a positive result would be limited to this synthetic task generator and fixed edit vocabulary; it would not show an autonomous new edit type, model-weight recursion or general intelligence growth.
