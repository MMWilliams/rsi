# Public-context AST specialist integration

Frozen before final labels on 2026-09-17. The AST specialist and parent evaluator are already fixed in `analysis/ast-feedback-model.json` and `analysis/temperature-ranker-development.json`. This is a fresh integration test; seeds 902294–902299 have no previous scored results in the project. Each seed generates 48 tasks, eight from each of six synthetic mechanisms, with one public example and 23 host-held examples. The last 15 host-held examples determine final correctness.

Candidate generation follows the prior mixed-mechanism source map at cap 128 per source. On AST tasks only, a proposed generator edit raises V67/V73 caps to 512. The candidate-source map uses the simulator's host family tag as in the prior study; evaluators and the gate receive only public examples and candidate programs. This limits the integration claim to this benchmark setup.

The gate routes to the AST specialist exactly when the public input's minimum codepoint lies in Unicode block 0x800; all other tasks retain the parent temperature-0.25 ranker. This rule was chosen from already inspected development mechanisms and is fixed before the new seeds. It is an intentionally simple benchmark context cue, not a learned general mechanism detector.

All choices are frozen before target labels are opened. Compare these policies on identical per-task wide pools: global parent 0.25, global AST specialist, gated AST specialist, prior fixed block-temperature map, and that fixed map with AST specialist substituted on block 0x800. Also score global parent 0.25 on old cap-128 pools to separate generator reachability from evaluator choice. Primary evaluator endpoint is gated specialist minus global parent on the same wide pools; report six paired bank differences and exact bank-bootstrap 95% interval. A positive integration signal requires at least five positive banks, a lower interval bound above zero, and no non-AST loss. Compare the combined gate with the strongest fixed map separately; it is not enough to beat the global parent alone.

Report candidate reachability, selected correctness by mechanism, acquisition labels already paid, generation time and candidate counts. Replay regenerated public tasks and pools, model choices, and final outcomes. This is a researcher-specified composition of two evaluator checkpoints, not improver growth. Later tests must give parent improvers the same catalog and feedback budgets, then measure which parent creates a better child improver from the same starting system.
