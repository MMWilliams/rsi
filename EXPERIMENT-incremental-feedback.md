# Incremental evaluator and improver feedback pilot

Frozen before generating transfer banks. This is a bounded feedback-learning pilot, not a recursive architecture invention test.

Use the already inspected semantic pools from `runs/policy-transfer-20260917b` as development data. E0 is a logistic correctness estimator fitted on that archive's 12 development tasks. In four successive rounds, add admission and the three previously observed transfer splits to feedback. All these old banks are now development evidence. Fit the same estimator from scratch on cumulative task-balanced feedback; retain its weights. Features are six program-operation counts, program length, two source indicators, and a bias. Only V67 and V73 candidates are used. Candidate labels come from the unchanged host interpreter.

The improver proposes two edits to the same frozen V67+V73 scoring policy. Its edit vocabulary is a fixed, authored menu of source priorities, length preferences and operation-weight changes. I0 proposes the first two menu entries. Later I checkpoints rank edits by their cumulative observed paired correctness gain over the same frozen base on feedback tasks. Record support, gain and harmful-change rate for every edit. Feedback evaluates every menu edit on the saved candidate pools; charge all such evaluations. This is learning which edits help, not inventing new edits.

Generate fresh transfer seeds 203301 and 203302, 12 mixed-family tasks each, eight visible and 13 hidden examples. Candidate cap eight per source. Deduplicate identical program strings in fixed V67-then-V73 order, retaining the first source consistently in feedback and transfer. No transfer hidden example enters fitting or edit proposal. Freeze all checkpoints and the transfer decisions before generating oracle labels. Measure evaluator selection accuracy and task-balanced Brier error on identical pools. For improver tests, reset to the frozen base each time, offer two policy edits, and let the designated evaluator select between those edits and the unchanged base. It may use the entire unlabeled bank to make one global edit choice. Measure the externally graded change in held-out correctness. This is declared transductive selection, not online test-label learning.

At each checkpoint test I0/E0, It/E0, I0/Et and It/Et. All have the same two-edit proposal allowance, the same pools, and the same base. Keep the base on ties. Also test a deterministic scrambled edit ordering with Et. Report proposal and candidate scoring counts, source generation time, model-fit iterations and feedback cost. Candidate acquisition is shared and is excluded from neither system's conceptual cost.

Log every checkpoint, prediction, edit choice and oracle outcome. Replay generation, feedback fits and choices and verify hashes in a separate audit. Two small transfer banks and one feedback curriculum support only a pilot result. No withheld-family, neural-weight growth, awareness, or child-improver claim. Do not change the recipe in response to final scores. Positive evaluator and improver transfer are separate endpoints; solver accuracy alone cannot pass either one.
