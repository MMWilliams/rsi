# Exhaustive single-fragment opportunity audit

Written before evaluating the sixteen previously unselected compatible source
additions. V7 and its source-only reopening diagnostic are already known.
This is retrospective diagnosis, not preregistered confirmatory evidence.

Reconstruct every source generation's candidate memory from its audited snapshot
and rerank on the archived public development tasks. Evaluate **every** remembered
fragment that is absent from the parent library and produces a nonempty substring
of each visible target on at least one task. Preflight counts are 36 source
menus, 60 qualifying additions, and 44 originally selected additions. The other
16 are the missing counterfactuals. Incompatible fragments cannot enter the
current atom pool on any of these tasks; this conclusion is specific to that
filter. Combinations of additions and changes to the filter are outside scope.

Use the corrected cost-reopening kernel, original parent settings, four-atom
limit and unchanged 128-expansion ceiling for both parent and candidate. Evaluate
all 36 parents, including menus with no available addition. No new proposal,
trajectory update, transfer task, admission query or final task is allowed.
Each result is replayed exactly and graded by the independent host oracle and
published interpreter on the archived source development examples.

Previously audited reopening evaluations may be reused only when the complete
request digest and kernel/dependency source hashes match. Retain the prior
payload and its archive provenance; distinguish reused work from fresh execution
and report the logical charges for the full comparison. Do not present reuse as
new independent evidence. Expected coverage is 96 distinct batch requests /
1,536 task outputs, of which 70 / 1,120 are available for verified reuse.

Report each fragment's signed gain, task wins/losses and program changes; mark
whether it was originally selected. For each menu report max(0, gain) over all
available additions and over the original top two. This is an oracle upper bound
on single-addition selection on the development data, not an implementable policy
or a final accuracy estimate. Positive missed opportunities justify investigating
ranking; zero positive opportunities mean better ranking alone cannot rescue
these fixed memories/parents/tasks. Neither result generalizes to all libraries.

Archive complete inputs, rankings, requests, outputs, selection flags, costs,
code snapshots, journal and failure record if needed. Independently reconstruct
candidate completeness, grades, pairings, upper bounds and reuse accounting.
Do not change the search kernel or protocol during the audit.
