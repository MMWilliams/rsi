## Provisional seed architecture

1. **Generate and journal candidates.** Use the verified V67/V73 search routes where the public task contract warrants them. Preserve candidate programs, source, cost, public context, visible examples and deterministic replay hashes. Track reachability separately from selection.
2. **Evaluate with a routed, frozen checkpoint.** On the three tested transition mechanisms, the listwise temperature-0.25 checkpoint is the strongest supported no-query evaluator. On the six-mechanism mixed contract, the fixed public-context temperature map is the zero-query base. The AST branch may widen its candidate pool and use the replay ranker. Route only from public features, with a fixed fallback when the specialist is outside its tested scope.
3. **Buy external evidence within a declared budget.** For a mixed 48-task bank with eight available calls, use the protected 24-feature candidate-conditioned interaction allocator after E0 reranking. Its earlier checkpoint scored 374/576 on the latest untouched panel versus the previous frozen allocator's 359 with 96 calls; its later checkpoint tied a matched-data 26-feature model at 370 while saving E1/7-leaf prediction work. Charge historical effect acquisition, E0 reranking, output prediction and exact calls separately. Keep the cheaper fixed schedules as resource controls. A simple AST-only action of one query per AST task remains supported; sequential AST allocation remains a research arm until its admission and parent-to-child gates pass.
4. **Record verified edit effects.** Each candidate edit has a name, parent checkpoint, affected component, acquisition and inference cost vector, admission result, external final-bank outcome, harms, task context and descendants. Store full positive and negative outcomes. Avoid treating the improver's own score as the oracle.
5. **Let the improver propose edits in a bounded catalog.** Start with candidate cap/source mix, listwise loss temperature, AST specialist route, output-sensor choice, query allocation and rollback. The improver predicts each edit's future gain and uncertainty from public context and prior verified effects. An admission gate compares it with the current fixed control on disjoint tasks and rejects measured harm. New edit types can be proposed later, but require replay, cost and external-sensor gates before entering the catalog.
6. **Test inheritance and recursion on identical bases.** Clone the same solver/evaluator/base improver for initial and later parent checkpoints. Give each equal new feedback and proposal/query allowances. Freeze the resulting children, then compare their ability to improve another identical base on untouched banks. Include empty, scrambled, duplicated, fixed-policy and outside-improver controls. Charge historical labels and candidate work separately.

## Primary measurement contract

- **Evaluator growth:** correct top choice on frozen candidate pools; reachable-but-missed candidates; false accepts; calibrated probability error where probabilities exist; and forecast error for query/edit utility. Keep pre-query, post-query and final correctness separate.
- **Improver growth:** realized external gain of the edit selected from the same base and candidate edit set at matched resource budgets; harmful accepted edits; regret against the available tested edits; and the later-parent child-minus-initial-parent child result on a second untouched bank.
- **System growth:** final correctness and coverage at fixed total resource vectors, including source acquisition, candidate execution, training, output queries and inference time. A fixed integration gain is useful but does not discharge the improver test.
- **Transfer:** mixed and withheld mechanisms, altered candidate generators, multiple learning seeds, and bank-level uncertainty. Synthetic string-task results do not transfer automatically to security, policy or social-good use.
