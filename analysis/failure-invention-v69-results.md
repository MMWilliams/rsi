# V69 failure-driven typed constructor invention

Status: audited two-seed result. V69 adds a failure-driven layer to the AST proposer. The legacy ordinal grammar is tried first; only tasks with no visible legacy solution activate a generic typed constructor layer. That layer proposes bit-count, parity, rotate-left, and gcd reductions, then evaluates them through the same executable span language. An evolutionary constructor genome selects which invented constructors to retain on development and must match or beat a broad-invention control on admission.

The held-out task family contains three mechanisms absent from the V66/V67 affine catalog: bit-count parity, 8-bit rotation followed by a residue test, and a gcd-derived bucket. No family label is passed to the proposer.

The evolved constructor architecture selected only `popcount` on both seeds. It passed the admission gate and matched the broad invention arm on fresh final banks. The legacy grammar failed visibly on 16/24 and 17/24 development tasks respectively; the corresponding failure-trigger counts were 20/24 and 13/24 on admission and 19/24 and 15/24 on final.

Both independent audits passed. Each replayed 216 evaluation rows and checked 19 sealed artifacts, for 432 rows and 38 artifacts across both replications. The audited archives are `runs/failure-invention-v69-20261005/` and `runs/failure-invention-v69-20261006/`.

## Interpretation

This is the strongest current evidence that the improver can respond to a measured representation failure by opening a new typed constructor layer and transfer the invented representation to hidden tasks. The evolutionary layer also compressed the broad proposal set to one reusable constructor family, `popcount`, on both seeds.

The result remains bounded recursive improvement, not proof of open-ended RSI. The novel constructor templates, mutation operators, visible target alignment, task generator, and admission protocol are researcher-authored. The hidden family is synthetic, and the proposer cannot invent a primitive outside the supplied typed constructor basis.

## Next discriminating test

Remove the named constructor basis: evolve short typed stack programs from a smaller bit-vector instruction set, allow the system to discover a reusable reduction such as bit-count parity, and evaluate on a new mechanism family whose implementation is absent from both the instruction templates and mutation catalog. Preserve the failure gate, held-out admission, compute accounting, and independent source replay.
