\title{A Seed That Grows by Testing Its Own Changes:\\ Persistent State Improvement Across Five Areas\\ and Three Development Seeds}
\author{Maureese Williams}
\date{October 11, 2026}

\begin{document}
\maketitle

\begin{abstract}
This paper studies a narrow form of self-improvement: can one persistent agent improve the state on which a fixed learning procedure operates, test each proposed change before keeping it, and carry the accepted state into settings with different structure? The state is the agent's accumulated experience, the models that guide its search, and the primitives from which it builds candidate solutions; the procedures that fit models, invent primitives and accept changes do not change. The agent solves rule-inference tasks over characters by searching a catalog of candidate predicates under a scan budget, and it can fail for two reasons: the right predicate exists but lies outside the budgeted portion of the catalog, or its current primitives cannot express it. Learned search guidance addresses the first, invention of primitives the second, and a pruning step removes inventions that never pay. A change is retained only when it solves more tasks than the current state on held-out worlds the agent never trained on, and a change to the shared primitives must also leave previously learned settings within a stated tolerance; that second condition was added after a change accepted in one setting cut a learned setting's score by 10\%. On held-out sets never used for acceptance, the main agent's solve rate in family-structured worlds rose from 17.1\% to 28.8\% over twelve experience cycles, and it rose in four further settings with different hidden structure; two agents started from other random seeds rose from 17.9\% to 26.1\% and from 15.0\% to 28.8\% in three cycles of the first setting, and in two further settings each, with one exception where a shared change passed a cross-area check too small to catch a 12\% loss. Learned search guidance was the most consistently accepted kind of change; invention paid off less often; untrained family combinations in the first setting ended 9\% below their start. The evidence comes from results inspected during development, without a prespecified success criterion, and the learning procedures are fixed throughout.
\end{abstract}

\section{Introduction}

An agent can improve its performance without improving the algorithm that teaches it. It can accumulate useful evidence, learn where to search, or acquire a new primitive that makes a previously inaccessible solution expressible. These are different forms of growth, and they can be carried forward or lost.

This research programme uses \emph{recursive self-improvement} to mean a system producing a successor with a better improvement procedure; that is the definition used here, not a universally accepted one. The present paper studies a narrower question: can one agent improve the persistent state on which a fixed learning procedure operates? That state includes its accumulated experience, the models that guide its search, and the primitives from which it constructs solutions. Changes to this state influence subsequent problem solving and the experience available for later updates, but the update procedures themselves do not change. The contribution is the integration and evaluation of several state-improvement mechanisms within one persistent agent, with an acceptance test that decides which changes remain.

Retaining improvements is straightforward only when their effects remain local. In this system the primitives are shared across settings. An update that helps the current setting can therefore change the search space of a setting learned earlier. The experiments expose exactly this failure and motivate testing shared changes wherever they will be used.

The agent is called a \emph{seed} because it is meant to be the thing that grows: a saved state plus fixed update procedures, run for successive cycles of experience. To avoid a clash with pseudorandom seeds, the paper says \emph{seed agent} or \emph{agent instance} for the artifact and \emph{random seed} for identifiers such as 644101.

\paragraph{Antecedents.} Each form of growth had been shown separately in this programme, in separate code. Within-life accumulation: an agent that keeps the atoms of whatever it submits, right or wrong, raised its own solve rate four to ten times across a hundred tasks at every scan budget from 128 to 4,096, and being told whether it was right added nothing. Learned search guidance: a grouping of primitives learned without labels from 1,600 worlds solved 6,993 and 8,077 more tasks over 18 budget cells than the same agent on a grouping from 400 worlds, on prespecified random seeds, audited. Expanded representational reach: in a string-manipulation language, a system that synthesised primitives from its failures solved 20 of 24 tasks where its fixed grammar solved 5, on two random seeds. None of these was recursive in the programme's sense; every attempt at a better child improver returned a null result. What they shared was a state that grew with experience and a learner that did not.

\section{The task, and the words this paper uses}

\subsection{A task in this system}

Each task asks the agent to infer an unknown Boolean rule over characters from a small set of visible examples. The agent searches a catalog of candidate rules and submits one that agrees with the visible examples. Hidden examples are reserved for evaluation. The search budget limits how many candidate rules the agent can inspect.

Here is one task from the implementation, drawn from a world whose hidden structure is described below. Characters are given by their code within a 256-character alphabet. The true rule is that bit 7 of the code is 0, that is, the code is below 128. Each visible example is a string whose longest prefix of characters satisfying the rule is the answer; the first three of the eight visible examples are

A candidate rule is consistent with an example when every character of the answer prefix satisfies it and the first character after the prefix does not. The agent's catalog at the start of this work has 82,758 candidate rules. Of these, 77 are consistent with all eight visible examples, and 17 of the 77 also reproduce the sixteen hidden examples. Scanning the catalog in its starting order with a budget of 1,024 rules, the agent meets exactly one consistent candidate, ``code below 144'', which is built from the single primitive \texttt{threshold:144} and its complement. It submits that rule. The rule fails a hidden example, so the task is not solved; the agent is not told this; and the primitive \texttt{threshold:144} enters its experience of this world as if it belonged there. The right rule, built from the primitive \texttt{bit:7:0}, was in the catalog all along but outside the 1,024 rules inspected. The agent's record of this submission notes that it found one consistent candidate in its window, which makes the submission a \emph{confident pick} in the sense defined below; on average such picks are correct 90\% of the time, and this one was not.

\subsection{Two hierarchies: how problems are generated, and how experience is scheduled}

Two organisations should be kept apart. On the generation side, an \emph{area} is a distribution over worlds with a particular hidden structure of primitive co-occurrence; a \emph{world} is one hidden set of 14 primitives, and every task of that world is drawn from a rule built only from them, so a world's tasks are related. On the schedule side, a \emph{life} is one cycle of experience and update: the agent lives 48 worlds of one area, 100 tasks each, and only then proposes and tests changes to its state. The task above came from a world of the first area, drawn from the families \emph{bit}, \emph{divmod} and \emph{gcd}.

\section{Why the agent fails, and what it does about it}

The agent can fail for two different reasons. A suitable predicate may already exist in its catalog but lie outside the portion inspected under the search budget, as in the task above. Alternatively, the current language may lack the primitives needed to construct it; the starting language omits two of the nine families, so a third of the rules in some worlds cannot be expressed at all. Learning a model can help with the first problem by changing which hypotheses are searched first. Extending the language can help with the second by adding new building blocks. Pruning addresses a related cost: added primitives enlarge the catalog and can dilute the budgeted search without improving performance. Two qualifications prevent misreadings. A task left without any consistent candidate is not proof that a primitive is missing; it means the budgeted search found none. And invention happens within a fixed expression grammar, not by unrestricted construction of new algorithms.

\subsection{What persists}

The carried state is the language; the experience, one record per world lived, with the area and the atoms behind the agent's confident picks and behind all its picks, by atom name so that the records survive a change of language; per area, a world and self model and a flag saying whether to build a search prior from that area's experience; the invented atoms and the life they entered; a ledger of every candidate change with its test; and the resource spent on living, testing and inventing. The language, the experience and the ledger are shared across areas; the model and the prior belong to an area.

\subsection{The operations}

\paragraph{Live collects evidence while solving related tasks.} The agent draws fresh worlds of an area and lives each as a stream of 100 tasks at the scan budget. Within a world, the atoms of each submission reorder the catalog for the next task, which is the within-life accumulation of the antecedents. Two carried objects reorder it further. The area's model, when it exists, turns the atoms earned so far in the current world into beliefs about which groups of atoms the world uses, and those beliefs promote the rows those groups build. The area's prior, when it exists, starts the scan from an order given by how often atoms co-occurred in the agent's own earlier worlds there, with half of each task's budget reserved for the order it would use with no prior at all. With neither, the agent scans in catalog order. The agent receives no correctness feedback on any submission.

\paragraph{Reflect uses accumulated evidence to improve future search guidance.} The world and self model describes both which primitives tend to occur together and how often the agent discovers particular primitives; its purpose is to use the agent's own submissions to guide subsequent search. Latent: a group label per atom, and which groups each world used. Observed: the confident picks of every world of the area. Fitted, by expectation-maximization: the labels, how often each set of groups occurs, and for each atom a \emph{discovery rate}, how often the agent finds the atom when it is present in a world, and an \emph{import rate}, how often the agent earns the atom through a wrong pick in a world where it is absent. An atom whose discovery rate falls below 0.10 is filed in no group: the agent meets it only through its own mistakes. Downstream, during a new world the collected atoms update the agent's beliefs about which groups are present, and those beliefs promote the corresponding hypotheses in the search order. The model's size, 6 to 8 groups and 2 to 4 groups per world, is chosen by the likelihood of the agent's last fifth of worlds in that area. The refit model and a prior from the area's experience form one candidate change. The fuller account of the model is in the companion paper.

\paragraph{Extend proposes additional primitives from uncovered tasks.} For the third of the life's worlds with the most tasks left without any consistent candidate, and only worlds with at least 15 such tasks, the agent enumerates expressions of depth one from the ordinal grammar and tests each against the constraints of the uncovered tasks, alone, complemented, or joined by and, or or xor to one atom it earned in that world. A candidate atom is proposed only if it fits at least two uncovered tasks: an atom a world is built from recurs across the world's rules, and a chance fit does not. The grammar yields 3,456 candidates distinct up to complement, searched smallest first; at most 40 atoms are proposed per life.

\paragraph{Prune proposes removing unused inventions.} An invented atom is proposed for removal two or more lives after it entered if it has never appeared in a confident pick, or if every area model that has seen it rates it as found only through wrong picks.

\paragraph{Prove determines whether a change deserves to persist.} After a life the agent proposes all three kinds of change at once and tests the combination; if the combination fails, it tests each part alone. A test runs the current state and the candidate on a held-out set of the area's worlds, drawn for that life and never lived. Under the rule in force at the end of this work, the candidate is accepted only when its gain over the current state, paired over the held-out worlds, has a 95\% bootstrap interval above zero; a candidate clearly behind on the first half of the set is stopped there. A candidate that changes the language is also run on a smaller held-out set of each other area the agent has lived in and is rejected if its total there falls more than 2\% below the current state's, a relative decrease on that set. Every held-out lifetime is charged to the agent's resource. The agent therefore receives aggregate performance feedback when selecting updates, though never per-submission feedback while collecting experience. Section~5 gives the history of this rule, which was revised twice during development, by the experimenter and not by the agent.

\section{Areas}

\paragraph{Mechanism worlds (\texttt{mech}).} A world draws three of seven families and its 14 atoms from their pooled atoms. The starting language lacks the two remaining families, popcount and xormod, so a world that uses one of them holds rules the agent cannot express. A fifth of the viable family triples are withheld from the agent's lives as \emph{untrained combinations}. Lives draw three quarters of their worlds from trained triples and a quarter from triples with an unfamiliar family; held-out sets hold equal numbers of trained, untrained and unfamiliar worlds.

\paragraph{Drawn partitions (\texttt{drawn7}, \texttt{drawn11}, \texttt{drawn13}).} Every atom of every family is assigned at random to one of a few groups; a world picks some groups and draws its 14 atoms from their union, and each atom slips to a uniformly random atom with some probability. The partition cuts across families, so nothing learned about mechanism worlds applies except the language. The three areas differ in structure: 9 groups with 3 per world and slip 0.15; 12 groups with 4 per world and no slip; 6 groups with 2 per world and slip 0.15. The agent is not told how many groups a world uses.

\paragraph{Metric worlds (\texttt{metric777001}).} Each atom has a behavioural descriptor, the normalised Fourier and Walsh spectra of its truth table over the alphabet. A sparse weighting over descriptor dimensions is drawn once and shown to nobody. A world is a centre atom together with the atoms nearest it under that weighting, fourteen in all, the centre included as the nearest to itself. A quarter of each life's worlds are centred on an atom of the two families the starting language lacks. Here the hidden structure is behavioural rather than syntactic.

\paragraph{Schedule.} A life is 48 worlds of 100 tasks at a budget of 1,024 scans per task. State is saved after every operation, so lives in different areas can be interleaved and a run resumed. The main agent, \texttt{s1} on random seed 644101, lived twelve lives in mechanism worlds, four in \texttt{drawn7}, four in \texttt{metric777001}, three in \texttt{drawn11} and two in \texttt{drawn13}, in that order except that mechanism lives 10 and 11 came last. \paragraph{Held-out sets.} An acceptance test uses 24 worlds per pool of the area (72 for mechanism worlds, 24 for a single-pool area), and the cross-area check 12 per pool. From version 11 of \texttt{s1} onward every life draws its own held-out set; the first eight mechanism lives (versions 0 to 10) reused one fixed set, and the numbers read on it carry the optimism that reuse allows. The reported gains come from one further held-out set per area, drawn with a salt no test used, on which the carried state and the starting state (starting language, no model, no prior) are run once each.

\paragraph{What the agent never sees.} A family label, a true world, which pool a world came from, or whether a submission was correct. Labels enter only in scoring, to say which pool a world came from and which family an invented atom reproduces.

\section{Results}

\paragraph{Did performance improve?} In ten of eleven agent-and-area pairs, yes. At a fixed budget of 1,024 scans per task, the main agent's mechanism-world solve rate on held-out worlds never used for acceptance rose from 17.1\% to 28.8\% over twelve lives (1,232 to 2,072 of 7,200 tasks), with one qualification: trained family combinations rose from 26 to 49 tasks per world and worlds with an unfamiliar family from 5 to 19, but untrained family combinations fell from 20.5 to 18.6 (Section~8). Figure~\ref{fig:growth} carries the overview and Table~\ref{tab:growth} the counts. Five-area coverage is the main agent's; the two further agent instances cover mechanism worlds for three lives and the first drawn partition and metric worlds for two lives each. The exception is \texttt{s3} in the drawn partition, where nothing was accepted in two lives on 24-world held-out sets and the retained state reads 280 to 246 on the untouched set: the loss came from an extension of 40 atoms accepted in metric worlds, which passed its 12-world cross-area check on the drawn partition (124 to 148) and failed on the larger untouched set. The cross-area check is too small.

\paragraph{Which updates were useful?} Model updates were the most consistently accepted kind of change: on the main agent a refit model was accepted on every mechanism life from 0 to 6 and on the first lives of every other area, and on \texttt{s2} and \texttt{s3} on all three mechanism lives. Language extensions were accepted less often, 6 of 24 proposed on the main agent, and every one proposed on \texttt{s2} and \texttt{s3} in mechanism worlds was rejected. Accepted removals, four on the main agent, took out 23, 26, 25 and 55 invented atoms. Over 26 versions the main agent accepted 16 models, 6 extensions and 4 removals and rejected 18 extensions, 6 models and 1 removal. These are acceptance outcomes, not a decomposition of the final gain: the rise on unfamiliar-family worlds, which the starting language cannot express a third of, needs invention, but the measurements do not separate invention's share from improved search.

\paragraph{What was invented?} At version 26 the language holds 111 invented atoms: 26 reproduce true popcount atoms and 29 true xormod atoms, the two withheld families, and 56 are behaviourally new. Invented atoms entered only through an accepted test. In metric worlds a model fitted from the first 48 worlds was alone worth 975 tasks on that life's held-out set, and in the drawn areas the agent chose four groups per world for the 12-group area, its true structure, and four for the 6-group area, where the truth is two.

\paragraph{What failed?} Two things, each of which changed the acceptance rule. A change accepted in one area damaged a learned area (Section~7). And the grown language, through atoms the agent's own model rated as never found, diluted the budgeted search on untrained combinations (Section~8). A third weakness was in the rule itself: on life 10 a model was accepted for a gain of 24 tasks on 72 worlds that read 82 lower on the untouched set, which is why acceptance now requires an interval above zero.

\paragraph{What did it cost?} By version 26 the main agent had spent 122.9 million scans living, 302.3 million testing, and 831,738 invention tests. Testing cost two and a half times living, because each life tested up to four candidates on 72 worlds against a freshly scored current state and the cross-area checks added to that. The per-life held-out totals the agent decided by are in the ledger; they lie within a few percent of the untouched-set numbers except for the life-10 case above.

\section{Interference across areas}

A change can improve the area that proposes it while damaging an area the agent has already learned. The first three-area check exposed exactly this failure.

After four lives in metric worlds, the main agent's score on the first drawn partition's untouched held-out set fell from 376 to 338, a 10\% loss in an area it had not entered since. The cause was the shared language. The metric lives had accepted one extension of 40 atoms and one removal of 25, each tested on the metric area alone, and a language that grew and shrank to suit metric worlds changed the catalog the drawn partition's model had been fitted over. Each change was an accepted success where it was tested and a regression where it was not.

The revision was to the acceptance rule, made by the experimenter at version 23: a candidate that changes the language is also run on a held-out set of every other area the agent has lived in, 12 worlds per pool, and is rejected if its total there falls more than 2\% below the current state's. The current scores of those areas are recomputed after any accepted shared change. The tolerance permits a small measured regression; it is a bound, not preservation. The cost is more held-out lifetimes per language candidate, which is why the combination of all proposals is tested first and the parts only if it fails.

The revised rule fired twice as soon as it existed. In \texttt{drawn11} a combination of invented atoms and a model gained 165 to 344 on that area's held-out set and was rejected because it cost mechanism worlds 8\% and \texttt{drawn7} 12\%; the model alone was then accepted, at 417. In \texttt{drawn13} a combination worth 150 was rejected for costing \texttt{drawn11} 23\%. Each would have been accepted under the earlier rule. The 	exttt{s3} case of Section~6 shows the rule's remaining gap: a 12-world check read a gain where a 24-world set read a 12\% loss.

\section{The grown language and the pools the agent cannot see}

The five-area check at version 24 showed, on the mechanism area's untouched set, that untrained family combinations had fallen from 24 to 18 tasks per world while trained worlds rose from 26 to 50. The acceptance tests had not seen it, because a test compares totals and the untrained pool is a third of the set.

An ablation of the retained state on that set attributes the loss (Table~\ref{tab:ablation}). The retained model and prior on the starting language score 1,973 with untrained combinations at 26 per world, above the start; the grown language alone, with no model and no prior, scores 735 against 1,299 for the starting language; the retained state scores 2,072 with untrained at 18. The 166 invented atoms then in the language, 110 of them behaviourally new, had enlarged the catalog from 82,758 rows to 266,272, and the half of each task's budget that the prior rule reserves for the no-prior order was scanning a catalog two thirds of which the agent had added. Trained worlds did not suffer, because the model's half of the budget found their rows anyway; untrained combinations, which the model promotes less, did.

The agent already held the verdict it needed. Its self model files an atom in no group when the agent would almost never find it in a world. Across the five area models, 107 invented atoms were rated real by at least one model, 55 of the 56 that reproduce a withheld family among them, and 59 were rated import-only by every model that had seen them, one of them real. From version 26 the pruning operation proposes those too, and the acceptance test decides.

Two further revisions went in at the same version, both to the test. The interval requirement replaced the strict-inequality rule after the life-10 case. And the tie-break, the order the scan uses among rows it scores equally, had been a random permutation of row indices, so adding or removing any atom reshuffled every other row and every language test carried that noise; it is now a hash of each row's content, so a language change changes nothing but the rows it adds or removes.

On life 11 the removal of the 55 atoms was accepted, +0.3 to +3.0 tasks per world on the mechanism set and better in all four other areas, and the model and extension proposed beside it were rejected on intervals that crossed zero. The language went from 426 to 371 atoms. On the untouched set untrained combinations now read 18.6 against a start of 20.5, inside the 10\% that the draft confirmation protocol allows, with every other pool and area above its start.

\section{What this does and does not show}

It shows one persistent agent improving its own state in five areas of different structure, and two further agent instances improving in three areas and two, keeping only changes it tested on worlds it never trained on, with the tests charged. The three forms of growth from the antecedents appear together in its ledger: within-life accumulation in every life, learned search guidance accepted nearly every life and accounting for most of the measured gain, and invented primitives that let it reach families its starting language could not express. Growth in one area did not require starting over in another; the language carried, and in the metric area a model fitted from 48 worlds was worth 975 tasks at once.

It is evidence from results inspected during development. The random seeds were used while the design changed, no success criterion was specified in advance, no forecast was committed, and no independent replay has audited the ledger. The held-out sets behind Table~\ref{tab:growth} were never used by an acceptance test, which is the one protection against the agent having tuned itself to its own scoreboard; but each is a single draw whose per-world results were not saved, so no interval accompanies those totals. Version snapshots and an auditor that replays accepted tests exist from version 26 on and have not yet been run.

It is self-improvement of state, not of procedure. The agent's model and language direct its search, its search produces the experience the next model and language are fitted from, and the ledger shows the state improving the state across twelve lives. But the procedures that turn experience into a model, candidates into atoms, and tests into acceptances are fixed code, and the two revisions of the acceptance rule were made by the experimenter. A later agent does not produce a better reflect or a better extend; the programme's definition of recursive self-improvement is not met.

The growth also saturates and is uneven. On the main agent's later mechanism lives few candidates passed, and model gains fell from hundreds to single digits by the sixth life. Untrained combinations in mechanism worlds ended 9\% below their start. Half of the remaining invented atoms are behaviourally new and some are surely junk that costs budget until a removal takes them out. Testing cost two and a half times living. And every area shares one task form and one catalog; the agent has not met a second domain.

\section{Lessons}

\begin{enumerate}[leftmargin=*]
\item The acceptance test is the design. Every choice that mattered concerned what counts as an accepted change: a paired interval above zero on a fresh held-out set, within tolerance everywhere the state is shared, cost charged. Given that rule, a weak candidate costs a test and nothing else, so the agent can propose freely.
\item Test the combination first, then the parts. This halved the tests in the common case and lost nothing.
\item Invention needs recurrence. An atom that fits one uncovered task is usually a coincidence; one that fits two is usually a missing atom. The first version accepted single fits, and every extension it proposed lost.
\item Let the agent remove what it added. Removing atoms that never earned their keep was accepted three times in three, and removing the atoms the self model called import-only recovered a loss no test had seen.
\item A model from 48 worlds can be worth keeping, when a test decides.
\item Shared state needs shared tests. The 10\% loss in an untouched area was invisible to any single-area test.
\item Score growth on worlds the agent never saw, and attach an interval. A gain of 24 on 72 worlds is noise.
\item Make the measurement stable under the change being measured. A tie-break over row indices turned every language change into a reshuffle of the whole catalog.
\item Build for the host. One stall and one crash in the record were the machine's shared memory, not the agent.
\end{enumerate}

\section{Next}

\begin{itemize}[leftmargin=*]
\item A prespecified success criterion on unused random seeds: after a fixed schedule of lives in three areas, the retained state beats the starting state on fresh held-out sets by a stated margin in every area, no pool falls below 90\% of its start, testing costs at most 2.5 times living, and every accepted change replays. The draft protocol exists; it is not frozen.
\item Intervals on the reported gains: save per-world results in the final checks.
\item Testing cost against test power: the half-set early stop is in, but the 12-world cross-area sets let a 12\% loss through and the 24-world sets of single-pool areas rarely admit a change under the interval rule; both need more worlds, which costs more, so the cost cut must come from stopping early, not from smaller sets.
\item A label-free guard for pools the agent cannot see, on the no-prior half of the budget, if the untrained-combination loss returns.
\item More areas and a second domain: a second task form and a second alphabet in the same catalog, then the string-manipulation tasks, which require the agent's solver to be one of several.
\item The next level: the agent improves its state, not its procedures. The first procedure it could plausibly improve is the acceptance test itself, learning from its ledger how large a held-out set each kind of candidate needs.
\end{itemize}
